# Zynum CPU bridge

This is the first runnable Scientific Platform integration of the Zynum
scientific branch. It uses Zig for arithmetic and the authoritative, header-only
Heteris descriptor contract for all views. The compiled scalar arithmetic
subset is imported directly from this repository's `src/` modules;
[UPSTREAM.md](UPSTREAM.md) records the source and the remaining migration gap.

## Build and test

The bridge uses the global **Zig 0.17.0** toolchain. Linux x86_64 is the first qualified target.
From this directory:

```sh
zig build -Doptimize=safe -Dheteris-include=/absolute/path/to/heteris/include
zig build -Dstandalone=true -Doptimize=safe -Dheteris-include=/absolute/path/to/heteris/include
zig build test -Dheteris-include=/absolute/path/to/heteris/include
zig build -Dshared=true -Doptimize=safe -Dheteris-include=/absolute/path/to/heteris/include
```

Default artifacts are `zig-out/lib/libzynum.a` and `zig-out/include/zynum.h`.
The shared option instead produces `libzynum.so` on Linux. The default
`-Dstandalone=false` excludes the provider. Explicit `-Dstandalone=true` adds
`libzynum-standalone.a` (or `.so` with `-Dshared=true`) and
`zynum_standalone.h`. Link both libraries for a standalone caller. Supply the installed
Heteris Data include directory or Heteris source `abi/include` explicitly. The
adapter is built within the complete Zynum checkout: its named source module
imports the original scalar/type/recurrence files without a copied source tree.
No Rust library, runtime loading, package download, or GPU SDK is required.
Use `--prefix`, `--cache-dir`, and the `ZIG_GLOBAL_CACHE_DIR` environment variable
to place outputs and caches elsewhere (Zig 0.17 removed `--global-cache-dir`).
Use a fresh prefix when checking the disabled standalone configuration: like
ordinary SDK installation, direct Zig installation preserves files installed by
earlier configurations and does not delete a previously installed provider.
On WSL, prefer caches in the Linux filesystem (for example under
`~/.cache/zynum`) if the Windows mount denies cache result renames. This bridge
uses LLVM and LLD explicitly. This configuration and the small `src/descriptor.c`
wrapper originated as workarounds for the previous Zig 0.16 linker and translate-c
issues. They remain part of the 0.17 qualification, retaining a single C validator
source and compatibility with plain C/C++ consumers.
Zig 0.17 C imports are generated by `addTranslateC` in the build graph and consumed
as the `zynum_c` module. The generated binding is a build artifact, not a second
hand-maintained ABI definition. Translation uses the installed compiler and does
not fetch a package during an offline build.
The public complex GEMM ABI retains its by-value two-double scalars. A thin C
wrapper forwards their components to Zig, avoiding the observed Zig 0.17 x86_64
SysV aggregate lowering issue after six integer-register arguments. Independently
compiled C callers verify both nonzero scalar components and error behavior;
the platform's `scripts/validate.py` also runs these consumers against debug and fast archives.

The standalone CMake project also qualifies a plain C consumer:

```sh
cmake -S . -B /tmp/zynum-build -DCMAKE_BUILD_TYPE=Debug -DZYNUM_BUILD_STANDALONE=ON -DHETERIS_ABI_INCLUDE_DIR=/absolute/path/to/heteris/include
cmake --build /tmp/zynum-build -j2
ctest --test-dir /tmp/zynum-build --output-on-failure
```

The parent platform can `add_subdirectory(libs/zynum)` and link target `zynum`.
Its Data interface dependency is `heteris_data`. `ZYNUM_BUILD_STANDALONE`
defaults to `OFF`; enable it to expose `zynum_standalone_provider`, which
transitively links `zynum`. The math target never links back to the provider.
The standalone header/library and plain C consumer are present only when enabled.
`zynum_zig_tests` remains registered with testing enabled in either mode;
`zynum_test_build` builds the selected CTest dependencies. CMake places Zig archives and
caches under its build directory, isolated per configuration, and installs the
archive, public header, source provenance and license texts. Upstream optimized
BLAS dispatch, GPU dispatch, and thread pools are not included in this bridge.

## Explicit execution resources

Include `zynum_standalone.h` and explicitly link `zynum-standalone` to access
the optional provider. Production `libzynum` has no naive implementation,
provider sequence state, or unresolved reference to it. Unit tests import the
provider through a test-only adapter, including when the production standalone
artifact is disabled.

`zynum_resources_create_naive` creates a small serial malloc/free provider.
Invoke its `allocate`, `map`, and `release` callbacks directly to manage storage;
destroy returns `HETERIS_BUSY` until every allocation is released. This mode
provides no pool, background thread, hidden budget, or implicit context.

`zynum_resources` aliases the authoritative `heteris_resources` provider table;
Heteris owns its field layout and callback declarations. Integrated mode supplies
the same callbacks using a real Heteris context. For
example, a C adapter can contain:

```c
static heteris_status map(void *u, heteris_storage s, void **p, uint64_t *n) {
    return heteris_storage_map(*(heteris_context *)u, s, p, n);
}
static heteris_status allocate(void *u, uint64_t n, uint64_t a, heteris_storage *s) {
    return heteris_storage_allocate(*(heteris_context *)u, n, a, s);
}
static heteris_status release(void *u, heteris_storage s) {
    return heteris_storage_release(*(heteris_context *)u, s);
}
/* ctx is a live explicit heteris_context; keep it alive for each call. */
zynum_resources r = { ZYNUM_ABI_VERSION, sizeof(zynum_resources),
    ZYNUM_MODE_INTEGRATED, 0, &ctx, allocate, release, map };
```

All three callbacks are required. Arithmetic kernels call `map` synchronously
and never allocate. Provider failures propagate unchanged; integrated mode never
falls back to the naive provider. Map/release synchronization and storage
lifetime are the caller's responsibility. Provider callbacks must return stable,
unique host ranges for live allocations. The naive provider is serial and not
safe for concurrent allocation/release. Its handles are process-local values.

## Arithmetic contract

`zynum_axpy_f64` computes `y = alpha*x + y`; `zynum_dot_f64` computes a scalar
inner product. Both accept rank-one F64 views with signed byte strides, including
read broadcasts. A contiguous 3D array can be given a separate flattened rank-one
descriptor for dot. Writable broadcasts and overlapping writable elements fail
Heteris validation. Axpy accepts exactly identical input/output layouts; other
intersecting storage intervals fail conservatively, including interleaved views.

`zynum_laplacian_periodic_3d_f64` applies the seven-point matrix-free finite
difference stencil to rank-three views. Each dimension wraps periodically. Supply
`inv_h2[d] = 1/(spacing[d]*spacing[d])`. Dimension lengths one and two work with
the same stencil, with repeated periodic neighbors. Input/output ranges must be
disjoint. Empty views access no bytes.

`zynum_gemm_f64` and `zynum_gemm_c128` implement rank-two
`C = alpha*op(A)*op(B) + beta*C` using an adapted upstream serial reference
loop. Operations support none, transpose, and conjugate transpose, with signed
strides, row/column-major storage, padding, and read broadcasts. Complex128
values use interleaved real/imaginary doubles. Scalars must be finite. C requires
WRITE, plus READ when beta is nonzero; beta zero never reads C. Zero alpha or
zero inner dimension skips A/B element reads and scales C. Every descriptor,
map and dimension is still checked in those branches and for empty output.
Conservative mapped C intervals must be disjoint from both inputs before any
write. This serial implementation supplies no optimized GEMM performance claim.

`zynum_spectral.h` exposes `zynum_chebyshev_series_f64` for
`sum_k c[k] T_k((H-center I)/half_width) X`, without endpoint halving. The caller
supplies the fixed synchronous block operator, finite enclosing interval, and
four packed workspace panels. No allocator or spectral-bound estimator is
implied. Output commits only after all callback and checked recurrence steps
succeed; workspace can change on failure. The header specifies disjointness,
finite-value requirements, and callback lifetime obligations.

Every kernel validates the resource table, Heteris descriptors, shape agreement,
permissions, mapped allocation lengths, and aliasing before any output write.
Non-finite alpha or nonpositive/non-finite `inv_h2` values fail without writes.
Array NaNs/Infs follow IEEE arithmetic. Dot uses serial, uncompensated scalar
summation. A successful call can therefore produce non-finite arithmetic results.

Tests cover signed and padded strides, scalar references, Fourier eigenvalues,
empty views, exact and partial aliases, malformed ranges, stale storage handles,
resource lifetime, explicit provider error propagation, invalid scalar parameters,
unchanged outputs on validation failures, and a descriptor stored inside output
memory (metadata is snapshotted before writes).

The GPU direction is capability-driven: Heteris owns device enumeration,
architecture metadata, precision support, memory budget and provider lifetime.
A future Zig backend must explicitly match those capabilities and the requested
memory space. This bridge implements CPU execution only; no GPU architecture or
model name is presumed and no GPU capability is advertised by Zynum.
